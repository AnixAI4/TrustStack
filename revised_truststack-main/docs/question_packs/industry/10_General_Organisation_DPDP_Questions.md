## 1. How to use this industry file

This file is a **general organisation overlay**. It should be used when an organisation does not clearly fit into a specialised industry template, or when the assessment is for a mixed/basic organisation where the first objective is to establish practical DPDP readiness.

The correct assessment design is:

```text
Core DPDP Compass 16-domain assessment
+ General Organisation overlay
+ Conditional packs: employees, customers, website/app forms, vendors, cloud/SaaS, marketing, CCTV/biometric, children, AI, breach, cross-border
+ Organisation-specific dynamic questions for departments, systems, vendors, branches, websites, apps and ROPA records
```

Use this template for:

- small and medium businesses;
- corporate offices and holding companies;
- NGOs, trusts, foundations and associations;
- clubs, societies and member-based bodies;
- local service businesses;
- training/coaching/service organisations not large enough for a specialist template;
- mixed organisations with basic CRM, HRMS, accounting, website, email and vendor systems;
- early-stage DPDP discovery where the industry is not yet classified.

Important positioning:

> The General Organisation template should be the safe default. It must not assume low risk simply because the organisation is small. Small organisations often process personal data through informal channels such as WhatsApp, email, spreadsheets, Google Drive, Excel, local laptops and outsourced vendors.

### 2.4 General organisation-specific DPDP distinction

| Processing context | DPDP Compass implication |
|---|---|
| Website lead forms | Notice, purpose, marketing consent, CRM transfer, retention and vendor mapping are required. |
| Employee and candidate data | HRMS, payroll, resumes, background checks, attendance, ID documents, performance records and exit data need lifecycle control. |
| Customer and prospect data | CRM, WhatsApp, sales calls, invoices, support tickets and payment references need inventory and retention. |
| Vendor and service-provider data | Vendor onboarding, procurement, contracts, KYC, bank details and contact persons are personal-data touchpoints. |
| CCTV/visitor/access logs | Purpose limitation, retention, access control and signage/notice practices should be checked. |
| Cloud/SaaS tools | Data location, access, sub-processors, deletion and breach notice must be reviewed. |
| Informal tools | WhatsApp, personal email, local Excel and shared drives are often the weakest data stores. |
| AI tools | Employees may upload personal data into public AI tools unless governed. |
| Branches/franchises/field teams | Data may be collected outside central systems and later digitised. |
| Mixed roles | Some activities may make the organisation a Data Fiduciary, while some outsourcing/client-service scenarios may make it a Data Processor. |

## 8. Key DPDP risks in general organisations

| Risk | Why it is common |
|---|---|
| Personal data hidden in spreadsheets and WhatsApp | Informal business operations and manual follow-ups |
| No single owner for privacy/data protection | DPDP seen as legal-only or IT-only topic |
| Weak notice at collection point | Generic privacy notice not connected to actual forms |
| Marketing data mixed with service data | CRM and campaign tools often lack consent separation |
| Vendor invisibility | SaaS, payroll, cloud, support and agencies process data quietly |
| Indefinite retention | Old leads, resumes, employee records and invoices are rarely deleted |
| Weak evidence | Policies may exist but implementation proof is missing |
| AI tool leakage | Employees may use public AI tools with customer/client/employee data |
| Cross-border unknown | SaaS and cloud data location often not reviewed |
| No breach playbook | Cyber incidents handled as IT issues without DPDP impact workflow |

## 18. Final implementation note

This General Organisation question bank should be used as the **default catch-all industry overlay** in TrustStack™ DPDP Compass.

It is especially useful for:

- first-time DPDP readiness discovery;
- organisations that do not know their data-processing landscape;
- small businesses and corporate offices;
- NGOs, trusts and associations;
- quick pilot assessments;
- mixed organisations where a specialist template is not yet appropriate.

The assessment should still remain evidence-driven. A low-risk industry label should never override actual processing facts such as children’s data, AI usage, cloud vendors, sensitive documents, biometric/CCTV systems, breach history or large-scale personal data processing.
